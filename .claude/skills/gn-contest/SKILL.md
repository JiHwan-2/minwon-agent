## 2. AI Agent 인정 기준

공식 정의: 목표를 이해하고 계획·판단하며, AI 모델·데이터·외부 도구/API로 **두 단계 이상의 업무를 수행**하고 **결과를 확인·수정**하여 목표 달성을 지원하는 시스템.

**6요소 중 최소 4개가 실제 작품에서 확인**돼야 함:

| 요소 | 심사 확인 내용 |
|---|---|
| Goal | 사용자 목표·문제 이해 |
| Planning | 작업 분해·순서 결정 |
| Reasoning | 상황에 따라 경로·도구·행동 선택 |
| Tool Use | API·DB·검색·파일·센서 실제 호출 |
| Memory/State | 이전 입력·상태·중간결과 활용 |
| Feedback | 결과 확인·수정·재시도 (API 오류 시 재호출 또는 대체 경로) |

인정 어려움: 1회성 프롬프트 출력, FAQ 챗봇, Tool 없이 텍스트 답변만, PPT만 있고 미동작.
높은 평가: 스스로 계획, **결과 오류를 확인하고 수정**, 실제 문제 해결.
시연 포인트(교육자료 D2): Agent가 **계획을 말하는 장면**, **Tool 호출 장면**, **결과를 수정·재실행하는 장면**, 실행 로그.

## 3. MVP 최소 완성요건 (Level 3 MVP가 목표)

1. 해결할 문제와 대상 사용자가 명확
2. 핵심기능 3~5개, 주요 기능 약 80% 이상 시연 가능
3. 최소 1개 End-to-End Workflow 실제 동작
4. AI/LLM이 판단·분류·추론·추천·계획 중 하나 이상 실질 수행
5. Tool/API/Data/파일/센서 최소 1개 실제 연동
6. 최소 UI 또는 명령 인터페이스
7. **대표 Test Case 5건 이상 수행·기록**
8. 3분 이내 실제 작동 시연영상 (또는 동등 현장시연)

## 4. 심사기준

### 4-1. 서류평가 (운영규정 별표 4 — **본선 추천 80점 이상**)

| 항목 | 배점 | 기준 |
|---|---|---|
| 자격체크 | 10 | 자격증빙 제출 10, 미제출 5 |
| 최종산출물 5종 | 20 | 5종 20, 4종 15, 3종 미만 10 |
| **시연영상 (AI Agent 구현성)** | **40** | 탁월 40, 우수 30, 보통 20 |
| 발표자료 | 20 | 우수 20, 보통 15, 미흡 10 |
| 기술설명서 | 10 | 우수 10, 보통 8, 미흡 5 (소스 미제출 시 5) |

→ **서류평가의 40%가 시연영상**. 영상에서 Agent 구현성(계획·Tool·판단·검증·재시도)이 보이는지가 본선 진출을 가른다. 5종을 모두 내야 20점.
서류평가 체크리스트(별표 4): 보고서 5p 이내 / 기술설명서 1p / 소스·저장소 접근정보 / 영상 3분 이내·실제 작동 / 발표자료 10장 이내 / 핵심기능 실제 동작 / E2E 시연 / AI의 실질 역할 / Tool 1개 이상 / Test Case 5건 이상 / 출처 신고 / 비밀키·개인정보 미노출 / 저작권 미침해.
1차 서류평가가 우수하면 발표 없이 제출물로만 평가할 수도 있다(제24·25조).

### 4-2. 본선 심사 100점 (운영규정 별표 5)

| 영역 | 배점 | 세부 |
|---|---|---|
| 주제 적합성·문제정의 | 15 | 주제 적합성 5 / 대상·문제 명확성 5 / 목표·성공지표 5 |
| **AI Agent 구현성** | **20** | 목표이해 4 / 계획·분해 4 / 판단·추론 4 / Tool 4 / Memory·Feedback 4 |
| **기술 구현·완성도** | **20** | End-to-End 8 / 핵심기능 완성·연동 6 / 안정성·Test Case 6 |
| 창의성·차별성 | 10 | 독창성 5 / 기존 방식·서비스 대비 차별성 5 |
| 실용성·사회/산업 효과 | 15 | 실제 적용가능성 6 / 효과측정 5 / 확장·사업화 4 |
| 데이터·안전·윤리 | 10 | 데이터·저작권 3 / 개인정보·보안 3 / AI 오류·편향·안전대책 4 |
| 비즈니스 모델 (시연·발표 포함) | 10 | BM모델·실행 5 / 설명력 2 / 질의응답 2 / 한계·개선계획 인식 1 |

- 가점: 규정상 **별도 최대 +5점**(세부기준은 규정 원문에 없음). 설명회 자료 기준 **+1**: 실제 사용자 3명 이상 또는 기관 담당자 피드백 증빙 (이름/소속, 피드백, 검증일자 확인서)
- 사회문제형(01) 비고: **공공/현장 데이터 활용 + 사회적 효과 정량 또는 검증자료**
- 주제 선택만으로 가점 없음
- 점수 산정(제29조): 심사위원 7명 이상이면 최고·최저 1개씩 빼고 평균, 가점은 평균 뒤 합산
- **동점 시 우선순위(제30조)**: ① AI Agent 구현성 ② 기술 구현·완성도 ③ 실용성·효과 ④ 주제 적합성
- 심사위원회는 **소스코드·커밋 기록·실행로그·데이터 출처·API 호출·신규개발분** 추가 확인을 요구할 수 있다(제30조) → git 커밋, 작업 기록(AgentLog), `docs/sources.md`, `docs/testcases/`, `docs/eval/`이 증거
- 완성도 Level(별표 3): **이 작품은 Level 3 (MVP, 대회 권장 목표)** = 핵심기능 3~5개로 E2E 1개 이상 안정 동작. 4 Pilot = 실사용자·실데이터·현장 조건에서 **반복** 검증되고 효과 확인 — 사용자 3명 1회 검증으로는 해당하지 않으므로 Level 4로 기재하지 않는다 (과장 기재는 허위 위험). 사용자 검증은 Level 3 작품의 효과측정·가점 자료로 쓴다

| 개발완료보고서 5p | 별지 4 (자유양식 또는 판넬형 이미지) | 1. 프로젝트 현황(제목·요약·팀명·팀원) 2. 개요(문제·사용자·목표) 3. 개발 세부(시스템 구조·활용 데이터·AI Tool/알고리즘·단계별 개발) 4. 구현 결과(기능·화면) 5. 기대효과(효과·성과·한계) |

개발완료보고서 필수 8요소(제22조): ① 문제와 사용자 ② 목표와 핵심기능 ③ Agent Architecture·Workflow ④ 사용한 AI·Tool·Data ⑤ 구현결과와 **테스트 5건 이상** ⑥ **기존자산과 신규개발분** ⑦ 정량 또는 정성 성과 ⑧ 한계 및 향후계획. 보고서는 문서 양이 아니라 실제 구현·신규개발분 확인용.

판넬형 보고서 예시(별지 4 이미지 2장, 설명회 16쪽): 한 장짜리 포스터. 머리말(작품명·한 줄 소개·팀명·팀원) → 01 프로젝트 개요(번호 4개 + 인용 상자) → 02 개발 세부 내용(1단계 수집 → 2단계 분석·판단 → 3단계 대응, 시스템 구성도 5칸 흐름, 활용 데이터·기술 띠) → 03 구현 결과(기능 목록 + 대시보드·모바일 화면) → 04 기대효과(문단) → 바닥글(주최·주관·후원).

## 6. 본선 발표·시연 (팀당 9분 = 발표·시연 6 + 질의 2 + 교체 1)

| 구간 | 시간 | 내용 |
|---|---|---|
| 문제 | 30초 | 누구의 어떤 문제 |
| Agent 설명 | 1분 | 목표·역할·핵심기능 |
| 구조 | 1분 | Workflow·AI·Tool·Data·Memory |
| **실제 시연** | **2분 30초** | 입력 → 판단 → Tool → 결과 |
| 성과 | 30초 | Before/After·사용자검증·효과 |
| 발전계획·BM | 30초 | 한계·현장 적용 전 보완점 |

- 운영규정 별지 3: **본선 시연은 제출 영상으로 발표·시연**한다 → 제출 영상의 완성도가 본선까지 그대로 간다
- (설명회 자료) 현장 네트워크·장비 장애는 제출 영상으로 대체 가능, 팀 시스템 자체 오류는 감점 가능 → 현장 시연을 하게 되면 Fallback·녹화본 필수
- 3분 영상 구성: 0:00 문제 → 0:30 입력 → 1:00 자동 실행 → 2:20 결과와 효과
- 예상 질문: **기존 ChatGPT와 차이 / 사용한 Tool / 실패 대응 / 팀 신규개발분**

## 7. 주의사항·필수요건

- **출처·신규개발분**: 생성형 AI(코딩도구 포함), 공개코드, 모델, API, 데이터, 템플릿, 기존자산의 출처와 **대회 기간(9/29~10/06) 신규개발분을 구분**해 제출. 사용 자체는 감점 아님
- 참가자 동의서 서약: "개발기간 외 사전 개발 … 부정행위를 하지 않겠습니다"
- 기존자산(제13조): 주제 공개 전 개발환경·계정·범용 템플릿·공개 라이브러리 준비는 허용, 기존 코드 사용 시 신규개발분과 구분 공개. 이 팀은 기존자산 없이 개발기간 중 신규 작성
- 중대 위반(제31조, 심사 제외·수상 취소): 출처 없는 도용·허위 자체개발 표시, **시연영상·성능수치·사용자검증·테스트결과 조작**, 중복참가, 악성코드·개인정보 불법 수집, 심사 공정성 훼손
- 저작권·라이선스: 오픈소스 라이선스, 데이터 이용약관, API 정책 준수
- 개인정보·보안: 불필요한 실제 개인정보 수집 금지, API Key·비밀번호·토큰 공개 금지
- 허위·조작 금지: 시연영상, 성능수치, 테스트결과, 사용자검증
- AI 오류·편향: 환각·편향·위해 가능성 고려, 사용자 확인·안전장치
- **제출 후 변경 금지**: 마감 후 핵심기능·소스 신규 추가·교체 불가, 형식오류만 지정시간 내 보완. 본선은 제출본 기준

## 8. 테스트케이스 5유형 (교육자료 D5)

정상 입력(기대 결과) / 부정확한 입력(확인 질문) / 데이터 없음(대체 방법 제안) / API 오류(사용자에게 설명) / 악의적 입력(개인정보·보안 차단). 각 건: 입력·예상결과·실제결과·수정내역 기록.

## 9. 이 프로젝트의 개발 원칙

- **모든 코드는 개발기간(9/29~10/06) 중 이 저장소에서 작성한다.** 개발기간 전 코드나 다른 프로젝트·폴더의 코드를 복사해 오지 않는다. 기획은 참가 신청서(9/18)를 따른다.
- 작업은 작은 단위로 커밋해 날짜별 개발 증거를 남긴다.
- AI 코딩도구·서비스 판단 엔진(Claude Code), 카카오 로컬 API, 오픈소스(LangGraph 등), 공공데이터는 사용 내역을 `docs/sources.md`에 누적 기록한다.
- 6요소를 **모두** 구현하는 것을 목표로 한다. 특히 **Planning(계획 표시)**, **Feedback(결과 검증·재생성)**, **입력 개인정보 마스킹**을 핵심 구조에 포함한다.
- 사회문제형 비고 요건: 공공/현장 데이터 활용 + 사회적 효과 정량 또는 검증자료 → Before/After 측정, 사용자 3명 검증(+1점).
