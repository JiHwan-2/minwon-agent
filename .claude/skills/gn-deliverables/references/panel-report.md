# 개발완료보고서 — 판넬형 (별지 4)

규정: A4 5페이지 이내(표지 제외) 또는 **판넬형 보고서를 이미지로 제출 가능**. 예시: `docs/reference/운영규정_별지4_판넬예시_1.png`, `_2.png`(세로형) + **`docs/reference/extract/설명회_16쪽.jpg`(같은 예시의 가로형 고해상도, 가장 자세함)** — 만들기 전에 다시 본다.
보고서는 문서 양이 아니라 **실제 구현과 신규개발분 확인용**(제22조). **예시 판넬처럼 한 장(01 개요 ~ 04 기대 효과)** 으로 만들고(팀장 결정 2026-10-05), 제22조 필수 8요소는 그 한 장 안에 넣는다: 테스트는 03에 9건 유형 목록, 신규개발분은 02-C 아래 "기존자산 없음" 한 줄, 한계·향후는 04 아래 두 줄. 판넬 2(검증·신규개발분 상세)는 만들지 않는다 — 아래 '판넬 2 내용'은 발표자료·출처신고서 재료로 쓴다.

## 예시 판넬의 구성 (그대로 따른다)

한 장 포스터. **가로형(설명회 16쪽)을 기본으로 한다** — 같은 예시인데 네 구역이 2×2 격자로 들어가 내용이 더 많이 들어간다 (세로형도 허용).

| 구역 | 가로형 예시의 구성 |
|---|---|
| 머리말 | 행사 표시 + 작품명 큰 글씨 + 한 줄 소개 + 팀명·팀원, 오른쪽에 상징 그림·구호 |
| 01 프로젝트 개요 (왼쪽 위) | 번호 1~4 문장(문제 → 현실의 어려움 → Agent의 목표 → 8일 MVP 완성) + 아래 인용 상자 |
| 02 개발 세부 내용 (오른쪽 위, 가장 큼) | **A. 시스템 구조도**(입력 → 수집 → AI 분석 → 판단 → 알림 5칸, 칸마다 아이콘·항목) / **B. 활용 데이터·AI 알고리즘·활용 기술** 3상자(체크 목록) / **C. 3단계 개발 내용**(단계마다 **일차 범위** 표시: 1단계 1~3일차, 2단계 4~6일차, 3단계 7~8일차) |
| 03 구현 결과 (왼쪽 아래) | 체크 표시 기능 목록 4개 + "8일 개발 완료 MVP 기준" 띠 + 실제 화면 캡처 2개(대시보드·모바일) |
| 04 기대 효과 (오른쪽 아래) | **이해관계자별 3열**(아이콘 + 체크 3개 + 인용 문구) |
| 바닥글 | 주최·주관·후원 (예시는 기관 로고 사용 — 우리는 공식 파일이 없으면 글자로만) |

## 판넬 2 내용 (재료)

- **테스트 결과**: TC1~TC8 표(유형·입력 요약·결과) — `docs/testcases.md` (기능이 크게 바뀌었으면 제출 전 `run_testcases.py`로 다시 돌린 결과)
- **평가 세트**: 담당 기관 정확도(경남 7개 시 11건, 3회 반복), 입력 확인·대화 판단(4개 언어), 흔들림 측정 — `docs/eval/README.md`. 한계(일부 문항을 개발 중에 사용)도 함께
- **신규개발분**: 날짜별 주요 개발(9/29 설계 → 10/1 골격·Tool·E2E → 10/2 판단 엔진·공공데이터·테스트·입력 확인 → 10/3 다국어·대화 → …) + "기존자산 없음, 전부 개발기간 중 이 저장소에서 작성" — `docs/sources.md`
- **출처 요약**: AI 도구(Claude Code: 코딩 보조·판단 엔진), 오픈소스(라이선스), API·데이터 — 출처신고서와 같은 내용 축약
- **한계·향후계획**: 지자체별 부서명 차이(일반 표현 사용), 판단 엔진 사용량·응답 시간, 번역 원어민 검토 없음, 사용자 검증 규모 → 지자체 조직도 연동, 사진 위치(진행 상황에 맞게), 기관 담당자 검증

## 만드는 법

1. 재료를 `docs/submission/panel/판넬.md`에 정리하고 사용자 확인 (문장은 판넬에 들어갈 길이로 짧게).
2. `docs/submission/panel/panel1.html`, `panel2.html`을 HTML/CSS 한 장으로 만든다: 가로형 1754×1240px(A4 가로 비율, 세로형이면 1240×1754), 외부 의존 없이 이미지는 `img/` 상대 경로, 글꼴 Pretendard(웹폰트) 또는 맑은 고딕, 색은 서비스 기본색(#1d5bd6 계열)로 통일. 구역 제목에 01~04 번호, 예시처럼 둥근 카드·아이콘(이모지 또는 단순 SVG). 사진·캐릭터 이미지를 지어내지 않는다.
3. 화면 캡처: `docs/submission/capture_screens.py`가 Edge를 화면 없이 띄워 실제 서비스에 시나리오를 입력하고 2배 해상도로 찍는다 (`img/`). 판넬용 조각(`img/p_*.png`)은 거기서 잘라 낸다.
4. 뽑기: `docs/submission/panel/render.py`가 PNG(3508×2480)·PDF(2쪽)를 만들고 넘친 칸을 알려 준다. 근거·확인할 것은 `docs/submission/panel/판넬.md`.
5. 결과 파일: `AI민원길잡이_개발완료보고서_판넬1.png`·`_판넬2.png` + 두 장을 묶은 PDF.

## 점검

- 제22조 8요소가 두 판넬 안에 모두 있는가 (위 배치 표로 하나씩 확인)
- 글자가 인쇄했을 때 읽히는 크기인가 (본문 14px 이상 @1754px 가로 폭, 예시처럼 칸마다 체크 목록·짧은 문장)
- Workflow ①~⑦·기능 이름이 기술설명서·발표자료와 같은가
- 수치·효과가 근거 파일과 일치하고, 측정하지 않은 것을 쓰지 않았는가
