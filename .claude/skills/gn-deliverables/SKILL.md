# AI민원길잡이 최종 제출물 만들기

규정·배점·양식의 원문은 `gn-contest` 스킬과 `docs/reference/운영규정_v1.0_20260907.md`(별지 1~4). 이 스킬은 **우리 작품으로 그 양식을 채우는 방법**이다.

## 제출물과 작업 순서

서류평가 100점 = 자격 10 + 5종 제출 20 + **시연영상 40** + 발표자료 20 + 기술설명서 10 (본선 추천 80점 이상). 본선 시연도 **제출 영상**으로 한다.
그래서 **기술설명서 → 시연영상 → 발표자료 → 판넬 보고서 → 출처신고서 → 최종 점검** 순으로 만든다. 기술설명서의 Workflow ①~⑦을 먼저 확정해야 영상 자막·발표 구조도·판넬 구성도가 같은 말을 쓴다(규정: 영상과 기술설명서의 연결성이 중요).

| 순서 | 제출물 | 분량·형식 | 상세 안내 |
|---|---|---|---|
| 1 | AI Agent 기술설명서 | 1페이지, 별지 1 표 양식 → `.docx` + `.pdf` | [references/tech-sheet.md](references/tech-sheet.md) |

| 4 | 개발완료보고서 | **판넬형**(별지 4 예시) 1~2장, 이미지(`.png`) + `.pdf` | [references/panel-report.md](references/panel-report.md) |
| 5 | 출처·AI 활용 신고서 | 자체 양식(공식 양식 확보 시 그 양식) | [references/source-declaration.md](references/source-declaration.md) |

## 시작 전 확인 (누가 만들든 같은 흐름이 되도록)

| 구분 | 확인할 것 | 없으면 |
|---|---|---|
| 최신 코드 | `git pull`로 `main`을 받았는가. 기능 브랜치에서 작업 중이면 `main`을 먼저 합친다 | 이 스킬·design.md가 옛날 판이라 이름·수치가 어긋남 |
| 원본 자료 | `docs/reference/`에 운영규정 md·판넬 예시 png·`extract/`(교육자료 글자, 설명회 슬라이드 그림)가 있는가 | git에 없는 파일(협회 저작물)이라 **팀장에게 폴더째 받아** 같은 위치에 넣는다 |
| 기능 반영 | 새 기능(예: 사진으로 위치 찾기)이 `main`에 병합됐다면 `docs/design.md` §2 F1~F5와 아래 Workflow ①~⑦에 반영됐는가 | **이 표를 먼저 고쳐 커밋**하고 제출물을 만든다. 제출물마다 따로 고치지 않는다 |
| 담당 | `docs/submission/README.md`의 담당 칸에 이름을 적고 커밋했는가 | 같은 제출물을 두 사람이 따로 만들게 됨 |

## 공통 규칙 (모든 제출물)

1. **사실은 근거 파일에서만 가져온다.** 기준 문서는 `docs/design.md`(구조·기능·Tool·안전장치), 수치는 `docs/testcases.md`(TC1~TC8), `docs/eval/README.md`(평가 세트·반복 실행), 신규개발분·출처는 `docs/sources.md`, 심사 항목별 근거는 `gn-contest` §11 근거 지도.
2. **만들기 직전에 수치를 새로 뽑는다.** 기능이 바뀌었을 수 있으므로 `pytest -q` 건수, `run_eval.py --compare` 결과, (기능이 바뀌었으면) `run_testcases.py`로 TC 재실행 결과를 다시 확인하고 그 값을 쓴다. 날짜와 실행 파일 이름을 함께 적는다.
3. **없는 성과는 쓰지 않는다.** 사용자 검증·Before/After 시간 단축은 **실제로 측정한 뒤에만** 숫자로 쓴다. 측정 전이면 '목표'·'측정 계획'으로 쓰거나 뺀다. 시연영상·테스트결과·사용자검증 조작은 수상 취소 사유(운영규정 제31조).
4. **완성도는 Level 3 (MVP)** 로 쓴다. Level 4라고 쓰지 않는다.
5. **같은 이름을 쓴다.** 작품명 `AI민원길잡이`, 판단 엔진 `Claude (Claude Code CLI, claude-opus-5-5)`, 단계 이름은 아래 Workflow ①~⑦, 기능 이름은 `docs/design.md` §2의 F1~F5.
6. **쉬운 한국어, 짧은 문장.** 심사위원이 30초 안에 읽을 수 있게 표·번호·그림 위주로. 전문용어는 처음 한 번만 풀어 쓴다.
7. **화면은 실제 서비스를 캡처한다.** 목업·합성 화면 금지. 캡처에 개인정보·API 키·로컬 경로가 보이지 않는지 확인한다.
8. **기관 로고·상표를 쓰지 않는다.** 대회 주최·주관 기관 로고는 받은 공식 파일이 있을 때만 쓰고, 없으면 글자로만 적는다.
9. 팀 정보: 창신대학교 컴퓨터공학과 김지환(팀장)·서준호, 대학부, 분야 01 사회문제 해결형 AI Agent. **팀명·역할 분담은 참가 신청서와 사용자에게 확인**하고 쓴다(커밋 작성자만 보고 정하지 않는다).

## 우리 작품의 Workflow ①~⑦ (모든 제출물 공통)

기술설명서 '핵심 Workflow', 영상 자막, 발표 구조도, 판넬 시스템 구성도에 **같은 번호·같은 이름**으로 쓴다.

| 번호 | 단계 | 하는 일 | Agent 요소 |
|---|---|---|---|
| ① | 입력·안전 점검 | 시민이 평소 말투로 불편을 입력(한국어·영어·중국어·베트남어)하거나 **현장 사진**을 올림 → 개인정보 가림, 긴급(112·119)·위기(109) 정해진 안내, 지시 주입 감지. 사진이면 촬영 위치(GPS)를 읽고 Claude가 사진 속 불편을 짐작해 예/아니요로 확인 | 안전, Perception |
| ② | 입력 확인·문제 분석 | Claude가 입력을 판단: 생활불편 민원 / **민원 서비스**(서류 발급·신고·신청 17종) / 다른 창구 / 불분명 / 민원 아님 + 유형·긴급도·언어. 민원이 아니면 대화로 답하거나 공식 다른 창구 안내, 불편이 여러 개면 하나만 처리하고 나머지는 따로 안내 | Goal, Reasoning |
| ③ | 처리 계획 | 할 일과 사용할 Tool을 계획해 화면에 표시 (빠진 단계는 코드가 보정, 민원 서비스는 서비스별 템플릿) | Planning |
| ④ | 정보 판단·추가 질문 | 부족한 필수 정보(위치·시간 등, 민원 서비스는 지금 위치·주소지)를 묻고 답을 이어받음. 사진 위치가 있으면 위치는 묻지 않음 (상태 저장, 대화 도중 질문·관계없는 말도 판단) | Reasoning, Memory |
| ⑤ | Tool 실행 | 카카오 지도(위치·관할 기관·가까운 기관·무인민원발급기), 지식베이스(담당 부서·절차·증빙, 민원 서비스 받는 방법·수수료), 공공데이터(비슷한 민원 사례·무인민원발급기 운영시간), 지금 운영 여부(공휴일 반영) (재시도·대체 경로) | Tool Use, Feedback |
| ⑥ | 판단·작성·검증 | 생활불편: 담당 기관·창구 판단 → 민원 초안·증빙 작성 → 규칙 검사 + AI 검토, 문제가 있으면 스스로 다시 작성. 민원 서비스: 지금 시각에 가장 좋은 방법 판단 (지어낸 연락처는 막음) | Reasoning, Feedback |
| ⑦ | 결과 전달·피드백 | 민원 패키지·PDF 또는 민원 서비스 안내 카드 전달(외국인은 번역본 + 제출용 한국어 원문), 수정 요청 반영(따를 수 없는 요청은 이유 안내), 시민이 직접 제출 | Feedback, Memory |

## 폴더와 도구

- 제출물 원본은 `docs/submission/` 아래 제출물별 폴더에 둔다 (`tech-sheet/`, `video/`, `slides/`, `panel/`, `source-declaration/`). **결과 파일(PDF·PNG·Word·PPT·영상·화면 캡처)은 대회 사이트로 따로 제출하므로 git에 올리지 않는다**(.gitignore, 팀장 결정 2026-10-05). 원본(md·html·css)·생성 스크립트·진행 표만 커밋한다.
- `.pptx`는 `anthropic-skills:pptx` 스킬, `.docx`는 `anthropic-skills:docx` 스킬로 만든다. 판넬은 HTML/CSS 한 장으로 만들어 브라우저에서 PNG·PDF로 뽑는다(panel-report.md).
- 제출물을 만들거나 고치면 `docs/submission/README.md`의 진행 표를 갱신하고 커밋한다.
