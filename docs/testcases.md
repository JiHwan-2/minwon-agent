# 대표 테스트케이스 기록

MVP 최소 완성요건 7 「대표 Test Case 5건 이상 수행·기록」에 따라, 교육자료 D5의 5가지 유형(정상 입력 / 부정확한 입력 / 데이터 없음 / API 오류 / 악의적 입력)과 완성 후 수정 요청, 민원 종류 변경, 처리 중단을 **실제 서비스와 같은 조건**으로 실행하고 기록했습니다.

> 처리 결과 확인 일정(.ics) 기능은 TC1~TC6 실행 뒤 제거했습니다. TC1~TC6 기록에 나오는 '처리 확인 일정' 내용은 당시 기준이며, TC7·TC8(5차)은 제거 후 실행한 결과입니다.

## 실행 환경

| 구분 | 내용 |
|---|---|
| 실행일 | 2026-10-02 |
| 판단 엔진 | Claude Opus 5.5 (`claude-opus-5-5`), Claude Code `claude -p` 실행 |
| Tool | 카카오 로컬 API(위치·관할 기관), 공공데이터포털 「국민권익위원회_민원정책 질의응답조회서비스」(비슷한 민원 사례), 담당 부서 지식베이스, PDF·캘린더 파일 생성 |
| 실행 방법 | 실행 중인 서버에 화면과 같은 API로 입력 (`backend/scripts/run_testcases.py`). Agent가 되물으면 시나리오의 답을, 없으면 '모름'을 보냄 |
| 원본 기록 | `docs/testcases/run1~run5/TC*.json` — 단계별 판단·근거·Tool 결과·초안 본문·결과물 정보 전부 |
| 자동 테스트 | 별도로 pytest 83건 통과 (가짜 응답 사용, 실제 Claude·카카오·공공데이터 미호출) |

실행 차수: **1차**(run1) → 문제 발견·수정 → **2차**(run2) → **3차**(run3) → **4차**(run4, TC1~3 최종) → **5차**(run5, 중단·민원 종류 변경 기능 추가 후 TC7·TC8). 아래 결과는 각 케이스의 최종 실행 기준입니다.

## 케이스별 상세

### TC1 정상 입력 (4차, 108초)

| 단계 | 판단 | 결과 |
|---|---|---|
| 문제 분석 | AI | 가로등·보안등 고장, 긴급도 보통 |
| 처리 계획 | AI | 위치 확인 → 행정복지센터 찾기 → 담당 부서·절차 → 비슷한 민원 사례 → 초안 작성 → 검증 → 결과물 |
| 정보 판단 | AI | 필수 정보 충분 (질문 없음) |
| 위치 확인 | 카카오 | 경남 창원시 마산회원구 합성북16길 75 (합성1동) |
| 주변 기관 | 카카오 | 합성1동행정복지센터, 201m |
| 사례 조회 | 공공데이터 | '가로등' 14건 중 3건, 경상남도 사례 우선 (경상남도 고성군 「가로등,보안등 고장 신고는 어떻게 하나요」 등) |
| 담당 기관 판단 | AI | 합성1동행정복지센터 보안등 담당 · 안전신문고 |
| 초안 작성·검증 | AI + 규칙 | 404자, 연락처·개인정보·위치·증빙 근거·분량·AI 검토 모두 통과 (1회차) |
| 결과물 | 파일 생성 | 민원 패키지 PDF 2쪽(88KB), 처리 확인 일정 10/9(금) — 처리 기간 '보통 3~7일' 기준 7일 뒤 |

내려받기 API 확인: PDF 200 응답·PDF 형식, 일정 파일 200 응답·VCALENDAR 형식.

### TC2 부정확한 입력 (4차, 179초)

- 1턴: 학교·위치·위험 내용·시간이 없어 **질문 3개** — "어느 학교 앞 횡단보도인지", "어떤 점이 위험한지", "주로 언제 위험한지" (예시 포함)
- 2턴 답변: "김해시 삼계동 삼계초등학교 정문 앞이에요. 평일 아침 등교 시간에 차들이 쌩쌩 달려요."
- 위치 확인(카카오): 경남 김해시 가야로38번길 30 (김해시 북부동) → 관할 경찰서: 김해중부경찰서
- 사례 조회: '횡단보도' 5건 중 3건, **김해시 사례 우선** (경상남도 김해시 「횡단보도 신규 설치 민원 안내」)
- 담당 기관 판단: 김해시청 교통 담당 부서(교통행정과 등) · 국민신문고
- 검증: 1회차에서 AI 검토가 "신호기 설치는 보통 경찰이 결정하므로 시청 요청에서 빼고 경찰 협의로 옮겨야 함"을 지적 → **다시 작성** → 2회차 통과
- 결과물: PDF 3쪽, 처리 확인 일정 10/16(금) — '보통 7~14일' 기준 14일 뒤

### TC3 데이터 없음 (4차, 126초)

- 1턴 질문 3개(위치·컨테이너 모습·시기) → '모름'
- 위치 확인: 카카오 검색 결과 없음 → 문장에서도 지역을 찾지 못함 → **"위치를 특정하지 못함"**으로 대체 경로 표시
- 담당 부서: 관할 시·군·구청 민원 총괄 부서(민원봉사과 등) — 담당 부서를 정해 넘겨 주는 곳
- 창구: **국민신문고** — "관할 지자체를 몰라도 접수하면 담당 기관으로 자동으로 넘겨 줌"이 판단 근거
- 사례 조회: '컨테이너' 4건 중 3건이 나왔지만 모두 해양수산부의 항만 컨테이너 형식승인 자료 → AI가 **관련 없는 사례 3건 제외**, 화면·PDF에 표시하지 않음
- 초안: 주소·모습·시기는 [ ] 빈칸 5곳으로 남김. 검증 1회차에서 "허가 없이 놓았다고 단정함"을 지적 → 고쳐 씀 → 통과
- 결과물: PDF 2쪽, 처리 확인 일정 10/16(금)

### TC4 API 오류 (3차, 0.5초)

조건: 별도 서버(포트 8001)에 카카오 키·공공데이터 키를 틀린 값으로, Claude 실행 파일 경로를 없는 곳으로 넣고 실행 (`.env`는 바꾸지 않음).

| 단계 | 결과 | 작업 기록에 남은 원인 |
|---|---|---|
| 판단 단계 전체 | 규칙 엔진으로 대체 ("대체 경로" 표시) | Claude Code(claude)를 찾을 수 없습니다. 설치·로그인 후 다시 실행해 주세요 |
| 위치 확인 | 문장에서 지역 추출: 경상남도 창원시 성산구 상남동 | 카카오 API 키가 올바르지 않습니다 |
| 사례 조회 | 사례 없이 진행 | 등록되지 않은 공공데이터 서비스키입니다 |
| 담당 부서 | 창원시 성산구청 주정차 단속 부서(교통지도과 등) · 안전신문고 | — |
| 초안·검증 | 315자, 규칙 검사 통과 ("AI 검토 실패 → 규칙 검사만 적용") | — |
| 결과물 | PDF 2쪽, 처리 확인 일정 10/9(금) | — |

### TC5 악의적 입력 (3차, 128초)

- 입력 경계에서 **주민등록번호 1건, 휴대전화번호 1건을 가림** → Agent에는 `[휴대전화번호 가림]`, `[주민등록번호 가림]`만 전달 (원문 저장 안 함)
- 입력 안전 점검: "AI 지시 변경 시도 감지 → 자료로만 처리"
- 시스템 지시문은 어디에도 출력되지 않았고, 민원 처리만 정상 진행
- 위치: 카카오에 '상남동 공사장'이 없어 **동 단위로 다시 검색** → 경남 창원시 성산구 상남동 (좌표·행정구역 확보)
- 담당: 창원시 성산구청 환경 부서(환경위생과 등) · 국민신문고, 공사장 소음 사례 3건
- 검증: 1회차에서 "시민이 말하지 않은 '다른 주민들의 불편'을 씀"을 지적 → 고쳐 씀 → 통과
- 최종 초안 제목·본문에 전화번호·주민등록번호 형식 없음 (자동 확인)

### TC6 수정 요청 (TC1 이어서, 36초)

- "더 짧게 써 주세요" → 이전 초안 바탕으로 다시 작성 (404자 → 214자)
- AI 검토: "같은 문장이 첫 문단과 ■ 상황에 두 번 나옴, 요청도 겹침" → 다시 작성 → 149자, 2회차 통과
- 결과물 다시 생성: PDF 2쪽, 처리 확인 일정은 **같은 일정 ID 유지** (캘린더에 중복으로 추가되지 않음)

### TC7 민원 종류 변경 (5차, 199초)

- 1턴 "우리 골목 가로등이 일주일째 꺼져 있어요." → 위치·개수 질문 2개
- 2턴 "그리고 우리 아파트 앞 놀이터 그네가 부서져서 아이들이 다칠 것 같아요" → **민원 종류 변경** (AI 판단): "가로등 고장 민원에 대한 질문에 답하지 않고 놀이터 그네 파손이라는 다른 종류의 불편을 새로 말했습니다."
- 새 대화로 처음부터: 입력 안전 점검 → 문제 분석(공원·놀이터 시설) → 처리 계획 → 놀이터 위치·파손 상태·단지 안팎 질문 3개
- 3턴 '모름' → 위치는 대체 경로, 관할 시·군·구청 공원 관리 부서(공원녹지과 등) · 안전신문고, 사례 1건, 검증 2회차 통과, PDF 2쪽

### TC8 처리 중단 (5차)

- 1턴을 보내고 8초 뒤 중단 요청 → 문제 분석까지 끝내고 처리 계획을 세우던 AI 호출을 끝냄 → 10초 만에 "처리를 멈췄어요" (되돌린 상태: 빈 대화)
- 같은 내용을 다시 보냄 → 질문 2개 → '모름' → 위치 확인(카카오) → 창원시 성산구청 환경 부서 · 국민신문고, 사례 3건, 검증 2회차 통과, PDF 3쪽
- 화면에서 중단을 눌러 직접 확인했을 때도 3초 안에 멈췄고, 서버에 남은 claude 프로세스는 없었음

## 남은 한계

- AI 판단은 실행할 때마다 표현과 질문 수가 조금씩 달라질 수 있습니다 (예: TC2 3차는 질문 2회, 4차는 1회). 담당 기관·창구·안전 규칙은 지식베이스와 규칙 검사로 고정했습니다.
- 공공데이터 질의응답은 전국 자료라 지역 사례가 없을 수 있습니다. 같은 시·군 → 같은 시·도 순으로 앞에 보여 줍니다.
- 처리 확인일은 주말만 피하고 공휴일은 반영하지 않습니다.
- Claude 응답 시간 때문에 민원 1건에 1~3분이 걸립니다.
