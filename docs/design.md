# AI민원길잡이 설계서

작성 2026-09-29 (1~2일차 설계) · 갱신 2026-10-04 (구현 반영) · 대회 분야: 01 사회문제 해결형 AI Agent
제출물(보고서·기술설명서·발표자료·영상)은 이 문서를 기준으로 쓴다. 구현이 바뀌면 이 문서부터 고친다.

---

## 1. 문제 정의 (1페이지 캔버스)

| 항목 | 내용 |
|---|---|
| **문제** | 시민이 생활불편(위험한 횡단보도, 고장 난 가로등, 소음 등)을 겪어도 담당 기관·부서, 제출 창구, 필요한 증빙을 몰라 여러 사이트를 헤매다 민원을 포기하거나 잘못된 곳에 제출한다. 한국어와 행정 절차가 낯선 외국인 주민은 더 어렵다. |
| **사용자** | 행정 용어와 민원 절차에 익숙하지 않은 일반 시민 (대표 사용자: 경남·창원 거주 대학생, 어르신 보호자, 경남 거주 외국인 주민) |
| **성과** | 민원 준비 시간 단축, 담당 기관 오지정 감소, 근거 없는 증빙 요구·누락 감소 |
| **데이터** | 사용자 자연어 입력, 카카오 로컬 API(주소·좌표·주변 기관), 생활불편 유형별 담당 부서·창구·절차·증빙 지식베이스(팀 작성), 공공데이터포털 「국민권익위원회_민원정책 질의응답조회서비스」(비슷한 민원 사례·처리기관) |
| **Agent 행동** | 입력 확인 → 불편 분석 → 처리 계획 수립 → 부족 정보 질문 → 위치·기관 검색 → 담당 기관·절차 판단 → 민원 초안 작성 → 스스로 검증·수정 → (외국인) 번역 → 결과물 |
| **제외범위** | 민원 자동 제출, 회원가입·로그인, 결제, 관리자 페이지, 전국 모든 기관 DB 구축, 음성 입력 |

**문제정의 1문장**
> 생활불편을 겪은 시민이 담당 기관과 절차를 찾고 민원을 작성하느라 수십 분을 쓰는 문제를, AI Agent가 대화로 필요한 정보를 모으고 담당 기관·절차·민원 초안·증빙 체크리스트를 5분 안에 준비하도록 돕는다.

**Agent 역할 1문장**
> 시민의 말을 민원으로 바꾸는 행정 길잡이 — 스스로 계획하고, 모자란 정보는 묻고, 검색으로 근거를 찾고, 결과를 검증한 뒤 건넨다.

**시연 성공조건 (반드시 성공해야 하는 장면)**
> "학교 앞 횡단보도가 너무 위험해요" 입력 → Agent가 계획을 보여줌 → 위치를 되물음 → 카카오 검색으로 관할 구청·경찰서를 찾음 → 민원 초안 생성 → 검증 단계가 문제를 찾아 스스로 고침 → 최종 민원 패키지 표시.

## 2. 핵심기능 (5개)

| # | 기능 | Agent 요소 |
|---|---|---|
| F1 | **입력 확인·생활불편 분석·처리 계획** — 생활불편 민원/민원 서비스(서류 발급·신고·신청 17종)/다른 창구/불분명/민원 아님 판단, 유형·긴급도·시민의 언어 판단(서로 다른 불편을 함께 말하면 하나만 이번 민원으로 정리하고 나머지는 따로 말하도록 바로 안내), 처리 계획(할 일·사용할 Tool)을 생성해 화면에 표시. 민원 서비스는 서비스별 템플릿으로 계획 | Goal, Planning, Reasoning |
| F2 | **추가 질문·대화** — 유형별 필수 정보 중 빠진 것을 질문하고 답변을 이어받아 진행. 현장 사진을 올리면 Claude가 사진 속 불편을 짐작해 '예/아니요'로 확인하고, 시민의 답(자유롭게 쓴 말 포함)이 예인지 아닌지 판단해 이어 감. 대화 도중 말을 이어지는 말/다른 민원/질문/관계없는 말로 판단. 민원이 아닌 말은 앞 대화를 기억해 자연스럽게 답함 | Perception, Reasoning, Memory |
| F3 | **위치·기관 검색** — 계획에 따라 Tool 선택·실행 (사진 촬영 위치(GPS)→주소, 위치 확인·후보 고르기, 주변 기관 검색, 지식베이스, 공공데이터 비슷한 민원 사례, 민원 서비스는 가까운 행정복지센터·구청·경찰서 등 9종 기관과 무인민원발급기(공공데이터 운영시간) + 지금 운영 여부), 실패 시 재시도·대체 경로 | Tool Use, Feedback |
| F4 | **담당 기관·절차 안내 + 민원 패키지 생성** — 기관·부서·창구·절차, 민원 제목·본문, 증빙 체크리스트(필수/권장/별도 절차, 근거 표시), 민원 패키지 PDF. 민원 서비스는 받는 방법(온라인·무인민원발급기·방문·전화)·수수료·준비물·기한과 지금 가장 좋은 방법을 안내 카드로. 외국인 시민은 시민의 언어로 | Reasoning, Tool Use |
| F5 | **결과 검증·수정** — 규칙 검사(확인되지 않은 연락처, 개인정보, 위치 포함, 근거 없는 '필수' 증빙, 분량) + AI 검토 → 문제 있으면 재작성(최대 2회), 사용자 수정 요청 반영(요청한 부분만 고치고, 따를 수 없는 요청은 이유를 답함), 처리 중 중단하면 직전 상태로 복원 | Feedback, Memory |

공통 안전장치: 입력 개인정보 마스킹, 긴급상황(112·119)·위기 표현(자살예방 상담전화 109) 정해진 안내, 지시 주입 감지, 다른 창구(소비자 피해·임금체불·사기·개인 간 분쟁) 공식 안내, 최종 제출은 사용자가 직접.

## 3. Agent Workflow

```
[시민 메시지]
  │ (코드) 개인정보 가림 · 위기 표현 감지 → 109 안내(정해진 문장, 시민의 언어)
  │
  ├─ 대화 도중이면 (Claude) 대화 도중 판단 ─┬─ 이어지는 말 → 그래프 이어서 진행
  │                                        ├─ 다른 민원   → 새 thread로 처음부터
  │                                        ├─ 질문       → 확인된 정보로만 답함, 진행은 그대로
  │                                        └─ 관계없는 말 → 정해진 안내, 진행하지 않음
  ▼
[guard]       (코드)   입력 안전 점검: 긴급상황·위기 표현·지시 주입 감지
[look]        (Tool·Claude) 사진을 올렸으면: 사진 정보(EXIF)에서 촬영 위치(GPS)·시각 읽기 → 카카오 좌표→주소,
                 Claude(이미지 입력)가 사진 속 생활불편을 짐작하고 확인 질문을 만듦. 긴급 장면이면 112·119 안내
[confirm_photo]        "도로에 나무가 쓰러져 … 불편하신가요?" 예/아니요 질문 (interrupt) → Claude가 답을 예/아니요로 판단
                 ├─ 예            → 사진 속 불편 + 촬영 위치·시각을 첫 입력으로 [understand]
                 ├─ 아니요 + 설명 → 시민이 말한 불편으로 [understand]
                 └─ 아니요만      → 어떤 점이 불편한지 다시 물음 (예/아니요를 모르면 한 번 더)
                 촬영 위치가 있으면 위치는 다시 묻지 않고 [locate]를 건너뜀. 없으면 기존처럼 대화로 위치 확인
[understand]  (Claude) 입력 확인 + 문제 분석: 민원 / 민원 서비스 / 다른 창구 / 불분명 / 민원 아님, 유형·긴급도·언어
                 ├─ 민원 서비스 (등본·가족관계증명서·여권·전입신고 등 17종, knowledge/services.json)
                 │    [svc_plan] (템플릿) 서비스별 계획: 받는 방법 조회 → (위치·주소지 질문) → 위치 → 기관·발급기 → 운영 여부 → 안내
                 │    [svc_check] ⇄ [ask] (Claude) 지금 계신 곳 / 주민등록 주소지(전입신고·복지·대형폐기물만) 확인 ⇄ 질문
                 │    [locate] ⇄ [confirm_location] (Tool) 카카오 위치 확인 (앞 질문에서 확정한 위치가 있으면 건너뜀)
                 │    [svc_act]    (Tool) 민원 안내 지식베이스 · 가까운 기관(카카오) · 무인민원발급기(카카오 + 공공데이터 운영시간) · 지금 운영 여부(한국 시간·주말·공휴일)
                 │    [svc_answer] (Claude) 지금 가장 좋은 방법·할 일·알아 둘 점 (지어낸 연락처는 정해 둔 안내로 교체), 끝
                 ├─ 민원 아님·불분명 → [chat] Claude 대화 (앞 대화 기억), 끝
                 ├─ 다른 창구       → 정해진 창구 카드(1372·1350·경찰·132), 끝
                 └─ 위기 표현       → 정해진 답, 끝
[plan]        (Claude) 처리 계획·Tool 선택 (빠진 단계는 코드가 보정, 화면 표시)
[check] ⇄ [ask]        필수 정보 판단 ⇄ 추가 질문 (interrupt로 멈추고 답변으로 재개, 최대 2회)
[locate] ⇄ [confirm_location]  (Tool) 카카오 위치 확인 ⇄ 후보가 여러 곳이면 시민이 고름
[act]         (Tool)   주변 기관(경찰서·행정복지센터) · 지식베이스 · 공공데이터 사례 (재시도·대체 경로)
[decide]      (Claude) 담당 기관·제출 창구·할 일 판단 (목록 밖 선택은 코드가 보정)
[draft] ⇄ [review]     민원 초안·증빙 ⇄ 규칙 검사 + AI 검토 (문제 있으면 다시 쓰기, 최대 2회)
[translate]   (Claude) 시민이 외국인이면 검증된 한국어 패키지를 시민의 언어로 번역
[deliver]     (Tool)   민원 패키지 PDF (한국어 원문)
  └ 완성 후 수정 요청 → [draft] 요청한 부분만 고침. 민원인 연락처 넣기·거짓·근거 없는 '필수'·담당 기관 바꾸기는
                        반영하지 않고, 무엇을 고쳤는지·반영하지 않은 이유를 시민의 언어로 답함
```

- 상태 관리: LangGraph StateGraph + 체크포인터 (세션별 thread_id). 추가 질문·위치 후보는 `interrupt` 로 멈추고 답변으로 재개
- 판단 엔진: 이 PC에 로그인된 Claude Code(`claude -p`)를 단계마다 실행. 단계별 지시문 + JSON Schema 출력 강제 + 도구 끔. 실패 시 그 단계만 규칙 엔진으로 대체하고 작업 기록에 표시
- 중단: 실행 중인 claude 프로세스를 끝내고(다음 단계도 시작하지 않음), 그 메시지를 보내기 전 체크포인트로 되돌림
- 모든 단계 결과는 스트리밍으로 화면 오른쪽 'Agent 작업 기록'에 전달 (판단 근거, 판단 엔진, Tool 호출·재시도, 검증 결과)
- 다국어: 한국어·영어·중국어·베트남어 (베트남·중국은 경남 외국인 주민 국적 1·2위). 대화·질문은 시민의 언어로, 민원 초안·PDF는 한국어 원문. 그 밖의 언어는 영어

## 4. Tool 목록

| Tool | 역할 | 입력 → 출력 | 실패 시 |
|---|---|---|---|
| `photo_meta` | 현장 사진의 사진 정보(EXIF)에서 촬영 위치(GPS)·촬영 시각 읽기 | 사진 → 위도·경도, 촬영 시각 | 정보가 없거나 망가졌으면 위치를 대화로 확인 |
| `reverse_geocode` | 사진 촬영 좌표 → 도로명·지번 주소·행정구역 (카카오 좌표→주소) | 위도·경도 → 경남 창원시 성산구 상남동 … 부근 | 1회 재시도 → 국내 주소가 없거나 실패하면 대화로 위치 확인 |
| `geocode` | 장소·주소 → 표준 주소·좌표·행정구역, 후보 최대 5곳 | "합성초등학교" → 경남 창원시 마산회원구 … (외국어·로마자 장소는 한국어 지명으로 바꿔 검색). 장소 이름이 다른 결과('창신대 버스정류장' → 노무법인)는 버림 | 1회 재시도 → 검색어를 줄여 다시 찾기(시·구 이름·'버스정류장·앞·근처' 같은 설명하는 말 빼기 → 뒤에서부터 한 단어씩) → 동 단위 검색 → 입력 문장에서 시·군·구 추출 |
| `find_nearby` | 좌표 주변 공공기관 검색 (관할 경찰서, 행정복지센터) | 좌표 + 기관 종류 → 기관명·주소·전화 | 건너뛰고 "관할 ○○" 일반 안내 |
| `kb_lookup` | 유형별 담당 부서·창구·절차·증빙 조회 | 유형 코드 + 지역 → 기관 후보·창구·절차·증빙 | 기타 유형(민원 총괄 부서·국민신문고) 안내 |
| `case_search` | 공공데이터 국민권익위 민원정책 질의응답에서 비슷한 민원 사례·처리기관 검색 → 판단 근거, 화면·PDF 표시 | 유형별 검색어 → 사례 제목·처리기관·등록일·국민신문고 원문 링크 (경남 우선, AI가 관련 사례만 선별. 제목을 누르면 질문·답변 원문) | 1회 재시도 → 사례 없이 진행 (키 없으면 건너뜀) |
| `service_kb` | 민원 서비스(17종)의 받는 방법·수수료·준비물·기한·주의할 점·찾아갈 기관 조회 | 서비스 코드 → 채널(온라인·발급기·방문·전화)·수수료·준비물 | 항상 성공 (지식베이스) |
| `find_offices` | 위치 주변 기관 검색 (행정복지센터·시군구청·경찰서·운전면허시험장·건보공단·세무서·등기소·병무청·차량등록사업소) | 좌표 + 기관 종류 → 이름·거리·전화·지도 링크·기본 운영시간 (시·군·구청은 이름 정확도 순으로 찾음: 가까운 순이면 '○○시청점' 가게·주차장이 먼저 나옴) | 1회 재시도 → 온라인·일반 안내 |
| `find_kiosks` | 가까운 무인민원발급기 (카카오) + 공공데이터포털 「행정안전부_무인민원발급기정보 조회서비스」 운영시간을 도로명 주소로 맞춤 | 좌표·시도 코드 → 발급기 이름·거리·설치 위치·평일/공휴일 운영시간 | 공공데이터가 안 되면 카카오 위치만 + "운영시간 확인 필요" |
| `check_hours` | 지금 시각(한국)·주말·공휴일(대체공휴일 포함)로 각 기관·발급기 운영 여부와 다음 평일 계산 | 기관·발급기 목록 → 운영 중 / 운영 안 함 / 확인 필요 | 운영시간을 모르면 "확인 필요" |
| `export_pdf` | 검증된 민원 패키지를 PDF로 생성 | 민원 패키지 → PDF (사용자 수정본 반영, 한국어) | 글꼴 없음 등 → 화면 복사 기능 안내 |

Tool 선택은 `plan` 단계가 유형·입력에 따라 결정하고, 빠진 필수 Tool은 코드가 보정한다 (예: 교통안전은 경찰서 검색, 층간소음은 주변 기관 검색 불필요).

- 공공데이터: 「행정안전부_무인민원발급기정보 조회서비스」(자동승인, 개발계정 하루 10,000건, 매일 갱신) — 발급기 이름·설치 위치·평일/공휴일 운영시간·사용 여부
- 공공데이터: 공공데이터포털 「국민권익위원회_민원정책 질의응답조회서비스」(자동승인, 개발계정 하루 10,000건)
  - 검토 후 제외: 「민원빅데이터 분석정보 API」(상세 명세가 별도 문서뿐이고 개발계정 100건 제한), 정부24 Open API(통계만 제공)

## 6. 예상 오류와 대응 (AI 오류·안전 포함)

| 예상 오류 | 대응 |
|---|---|
| 카카오 API 키 없음·호출 실패 | 재시도 후 동 단위·문장 기반 지역 추출로 대체, 작업 기록에 "대체 경로" 표시 |
| 장소 표현이 지도에 그대로 없음 ('창신대 정문 버스정류장 기준 가장 가까운 횡단보도') | 검색어를 줄여 다시 찾아 장소(창신대학교)·관할 기관까지 확정하고, 시민이 말한 위치 표현은 초안에 그대로 씀 |
| 위치가 모호함 ('창원 초등학교') | 다시 묻고, 후보가 여러 곳이면 시민이 고름. 끝내 모르면 1순위 후보 + 확인 필요 경고 |
| LLM 응답 지연·실패 (미설치·로그인 만료·시간 초과·일시 오류) | 일시 오류 1회 재시도, 그래도 실패하면 그 단계만 규칙 엔진으로 대체하고 원인 표시 |
| 공공데이터 키 없음·호출 실패 | 사례 조회만 건너뛰고 지식베이스로 진행 |
| 엉뚱한 입력(의미 없는 말·잡담·장난) | 입력 확인에서 민원 흐름을 시작하지 않고 대화로 답함. 대화 도중이면 진행하지 않고 같은 질문을 다시 보여 줌 |
| LLM이 없는 사실·연락처를 만들어냄 | 초안: 검증 단계에서 허용 목록 외 전화번호·주소 차단, 말하지 않은 사실은 [ ] 빈칸. 대화: 확인되지 않은 연락처가 있으면 정해진 문장으로 교체 |
| 근거 없는 '필수' 증빙 | 지식베이스에 공식 요건이 있는 것만 '필수', 나머지는 검증 단계가 '권장'으로 낮춤 |
| 행정 민원이 아닌 일 (택배·환불·임금체불·사기·개인 간 분쟁) | 시·군·구청 대신 공식 다른 창구 카드로 안내 (번호·주소는 지식베이스 값) |
| 긴급상황·위기 표현 | AI 판단과 관계없이 112·119 / 자살예방 상담전화 109를 정해진 문장으로 먼저 안내 |
| 입력에 개인정보·지시 주입 | 개인정보 마스킹, 지시 주입은 자료로만 처리하고 감지 표시 |
| 처리가 오래 걸리거나 잘못 보냄 / 서버 오류 | 중단 버튼 → 직전 상태로 복원, 같은 내용으로 다시 보내도록 안내 |
| 번역 실패 | 한국어 원문을 그대로 보여 줌 |
| 서로 다른 불편을 한 번에 말함 ('가로등도 꺼졌고 쓰레기도 쌓였어요') | 더 급하거나 먼저 말한 하나만 이번 민원으로 정리하고, 나머지는 담당이 다를 수 있으니 이 민원을 마친 뒤 따로 말해 달라고 바로 안내 (말없이 빠뜨리지 않음) |
| 초안에 시민이 말하지 않은 짐작·같은 내용 반복 | 작성 규칙으로 막고, AI 검토가 찾으면 다시 씀 |
| 서류 발급·신고를 물었는데 생활불편 민원으로 처리됨 | 입력 확인에서 '민원 서비스'를 따로 판단해 안내 흐름으로 (고칠 불편이 함께 있으면 민원). 맞는 서비스가 없으면 무엇을 하려는지 되물음 |
| 지금 닫힌 기관을 추천 | 한국 시간·주말·공휴일(대체공휴일 포함)로 운영 여부를 코드가 계산하고, 닫혀 있으면 온라인·운영 중인 발급기를 먼저 권하고 다음 평일 날짜를 알려 줌 |
| 무인민원발급기 공공데이터 미신청·오류 | 카카오로 찾은 위치만 보여 주고 "운영시간 확인 필요" 표시 |
| 수수료·운영시간이 지자체마다 다름 | 지식베이스에 "지자체에 따라 무료" 등 범위를 적고, 카드에 근거·확인일과 "방문 전 확인" 안내를 항상 표시 |
| 사진에 촬영 위치(GPS)가 없음 (메신저로 받은 사진·위치 저장을 끈 카메라 등) | 기존 방식대로 대화로 위치를 묻고 지도 검색 |
| 사진 분석 실패 (Claude 미설치·오류) · 사진에서 불편을 못 찾음 | 공공장소 사진이면 뚜렷한 파손이 없어도 가장 그럴듯한 불편을 짐작해 묻게 함. 그래도 못 찾으면 설명을 부탁하거나(글이 없을 때) 함께 쓴 글로 진행하되, AI가 본 장면을 뒤 단계에 넘겨 대화에서 "사진을 볼 수 없다"고 답하지 않게 함. 시민이 "사진 보고 찾아 줘"라고 하면 사진을 한 번 더 봄 |
| 시민의 답이 예/아니요로 분명하지 않음 | 한 번 더 예/아니요로 묻고, 그래도 모르면 답한 말 그대로 문제 분석에서 판단 |
| 사진 속 얼굴·차량 번호판·글자로 된 지시 | 분석 지시문에서 개인정보는 쓰지 않게 하고, 사진 속 글자는 자료로만 봄 |
