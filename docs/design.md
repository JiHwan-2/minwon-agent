# AI민원길잡이 설계서 (1~2일차 산출물)

작성일: 2026-09-29 · 대회 분야: 01 사회문제 해결형 AI Agent

---

## 1. 문제 정의 (1페이지 캔버스)

| 항목 | 내용 |
|---|---|
| **문제** | 시민이 생활불편(위험한 횡단보도, 고장 난 가로등, 소음 등)을 겪어도 담당 기관·부서, 제출 창구, 필요한 증빙을 몰라 여러 사이트를 헤매다 민원을 포기하거나 잘못된 곳에 제출한다. |
| **사용자** | 행정 용어와 민원 절차에 익숙하지 않은 일반 시민 (대표 사용자: 경남·창원 거주 대학생, 어르신 보호자) |
| **성과** | 민원 준비 시간 단축, 담당 기관 오지정 감소, 증빙 누락 감소 |
| **데이터** | 사용자 자연어 입력, 카카오 로컬 API(주소·좌표·주변 기관), 생활불편 유형별 담당 부서·창구·절차 지식베이스, 공공데이터(후보: 아래 5절) |
| **Agent 행동** | 불편 분석 → 처리 계획 수립 → 부족 정보 질문 → 위치·기관 검색 → 담당 기관·절차 판단 → 민원 초안 작성 → 스스로 검증·수정 |
| **제외범위** | 민원 자동 제출, 회원가입·로그인, 결제, 관리자 페이지, 전국 모든 기관 DB 구축, 음성 입력 |

**문제정의 1문장**
> 생활불편을 겪은 시민이 담당 기관과 절차를 찾고 민원을 작성하느라 수십 분을 쓰는 문제를, AI Agent가 대화로 필요한 정보를 모으고 담당 기관·절차·민원 초안·증빙 체크리스트를 5분 안에 준비하도록 돕는다.

**Agent 역할 1문장**
> 시민의 말을 민원으로 바꾸는 행정 길잡이 — 스스로 계획하고, 모자란 정보는 묻고, 검색으로 근거를 찾고, 결과를 검증한 뒤 건넨다.

**시연 성공조건 (반드시 성공해야 하는 장면)**
> "학교 앞 횡단보도가 너무 위험해요" 입력 → Agent가 계획을 보여줌 → 위치를 되물음 → 카카오 검색으로 관할 구청·경찰서를 찾음 → 민원 초안 생성 → 검증 단계가 문제를 찾아 스스로 고침 → 최종 민원 패키지 표시.

## 2. 핵심기능 (5개)

| # | 기능 | Agent 요소 |
|---|---|---|
| F1 | **생활불편 분석·처리 계획** — 유형 분류, 긴급도, 처리 계획(할 일·사용할 Tool)을 생성해 화면에 표시 | Goal, Planning |
| F2 | **추가 질문** — 유형별 필수 정보 중 빠진 것을 판단해 질문하고, 답변을 이어받아 진행 | Reasoning, Memory |
| F3 | **위치·기관 검색** — 계획에 따라 Tool 선택·실행 (주소 검색, 주변 기관 검색, 지식베이스), 실패 시 대체 경로 | Tool Use, Feedback |
| F4 | **담당 기관·절차 안내 + 민원 패키지 생성** — 기관·부서·창구·절차, 민원 제목·본문, 증빙 체크리스트 | Reasoning |
| F5 | **결과 검증·수정** — 규칙 검사(개인정보, 빈칸, 허용 URL, 핵심 사실 포함) + AI 검토 → 문제 있으면 재작성, 사용자 수정 요청도 반영 | Feedback, Memory |

공통 안전장치: 입력 개인정보(전화번호·주민등록번호·이메일 등) 탐지·마스킹, 최종 제출은 사용자가 직접.

## 3. Agent Workflow

```
 입력 ─▶ [guard] 개인정보 마스킹
            │
            ▼
        [understand] 유형·요약·긴급도 ──▶ [plan] 처리 계획·Tool 선택 (화면 표시)
                                              │
                                              ▼
                     ┌──────────────── [check] 필수 정보 충분?
                     │  부족(최대 2회)          │ 충분
                     ▼                         ▼
               [ask] 질문 ⏸ 사용자 답변      [act] 계획된 Tool 실행
                     │                        (실패 → 재시도 → 대체 경로, 실행 로그)
                     └────▶ check              │
                                              ▼
                                         [decide] 담당 기관·절차 판단
                                              │
                                              ▼
                                         [draft] 민원 초안·증빙 체크리스트
                                              │
                                              ▼
                                         [review] 규칙 검사 + AI 검토
                                          │ 문제 있음(최대 2회)     │ 통과
                                          └──▶ draft (피드백 반영)  ▼
                                                               [출력] 민원 패키지
                                                                    │ 사용자 수정 요청
                                                                    └──▶ draft
```

- 상태 관리: LangGraph StateGraph + 체크포인터 (세션별 thread_id)
- 추가 질문: LangGraph `interrupt` 로 멈추고 답변으로 재개
- 모든 노드 결과는 스트리밍으로 화면에 전달 (진행 단계, 계획, 실행 로그, 검증 결과)

## 4. Tool 목록

| Tool | 역할 | 입력 → 출력 | 실패 시 |
|---|---|---|---|
| `geocode` | 장소·주소 → 표준 주소·좌표·행정구역 | "합성초등학교" → 경남 창원시 마산회원구 … | 1회 재시도 → 입력 문장에서 시·군·구 추출 |
| `find_nearby` | 좌표 주변 공공기관 검색 (경찰서, 행정복지센터) | 좌표 + 기관 종류 → 기관명·주소·전화·거리 | 건너뛰고 "관할 ○○" 일반 안내 |
| `kb_lookup` | 유형별 담당 부서·창구·절차·증빙 조회 | 유형 코드 + 지역 → 기관 후보 | 기타 유형(국민신문고) 안내 |
| `public_data` (후보) | 공공데이터로 근거 보강 | 5절 참고 | 생략하고 지식베이스만 사용 |

Tool 선택은 `plan` 노드가 유형·입력에 따라 결정한다 (예: 층간소음은 `find_nearby` 불필요, 교통안전은 경찰서 검색 필요).

## 5. 데이터

- 지식베이스: 생활불편 12개 유형 × (담당 부서, 역할, 제출 창구, 절차, 증빙, 처리 기간) — 지자체 공개 조직도·안전신문고·국민신문고 안내를 참고해 팀이 작성, 출처 기록
- 공공데이터 후보 (3일차에 이용 가능 여부 확인):
  - 공공데이터포털: 법정동/행정동 코드 → 행정구역 정규화
  - 공공데이터포털: 민원 관련 통계·사례 데이터 → 유형별 빈도·근거 표시
  - 경남·창원 지자체 조직·부서 정보
- 개인정보: 실제 개인정보 저장 안 함, 세션 메모리만 사용, 입력 마스킹

## 6. 예상 오류와 대응

| 예상 오류 | 대응 |
|---|---|
| 카카오 API 키 없음·호출 실패 | 재시도 후 텍스트 기반 지역 추출로 대체, 실행 로그에 "대체 경로" 표시 |
| LLM 응답 지연·실패 | 사용자용 오류 메시지, mock 모드(규칙 기반)로 시연 가능 |
| 위치를 끝내 알 수 없음 | "관할 시·군·구청" 일반 안내 + 국민신문고(자동 이송) 추천 |
| LLM이 없는 사실·전화번호를 만들어냄 | review 단계에서 허용 목록 외 URL·전화번호 차단, 사실은 [ ] 빈칸 처리 |
| 입력에 개인정보 포함 | guard 단계 마스킹 + 안내 |
